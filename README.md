# مفردات – Vocab App

تطبيق لتعلم الكلمات الإنجليزية: المستخدم يكتب الكلمة بس، و**Gemini** يجهّز المعنى (إنجليزي + عربي)، الأمثلة، التصنيف، المرادفات والعكس. بعد كده يقدر يعمل اختبارات مبنية على كلماته، وكل كلمة يغلط فيها بتتضاف لـ `week_words` (نقاط الضعف) عشان الاختبار الجاي.

وفيه كمان **مراجعة متباعدة بخوارزمية FSRS** (نفس خوارزمية Anki الحديثة) وتذكير يومي بإشعارات Web Push. التفاصيل في آخر الملف.

## التشغيل

```bash
cd server
npm install
# ضع القيم في server/.env (انسخ من .env.example): MONGO_URL, JWT_SECRET, GEMINI_API_KEY
npm start          # http://localhost:3000  (الواجهة من server/public)
npm test           # اختبارات المنطق (بدون قاعدة بيانات ولا مفتاح Gemini)
```

## المراجعة المتباعدة (FSRS)

الحسابات كلها بتتعمل بمكتبة **[ts-fsrs](https://github.com/open-spaced-repetition/ts-fsrs)** الرسمية، مش نسخة مكتوبة باليد.

- **الإصدار المثبّت: `ts-fsrs@5.2.3`** (آخر إصدار من فرع 5 بيدعم Node 18). الإصدارات الأحدث (5.3+) بتطلب Node 20، ومعلن في المشروع `node >=18`، فما رفعناش إصدار Node. لو بيئة النشر عندك Node 20+ تقدر ترقّي المكتبة بأمان.
- الإعدادات: القيم الافتراضية للمكتبة، والاحتفاظ المستهدف 0.9 (`FSRS_REQUEST_RETENTION` لو عايز تغيّره). الـ fuzz مقفول عشان الفترة اللي على الزر هي نفسها اللي بتتحفظ. **المعاملات مش مخصصة لذاكرة المستخدم**: مفيش محسّن (optimizer) متنفّذ لسه، والخوارزمية بتشتغل بمعاملاتها الافتراضية.
- حالة كل كلمة (`due, stability, difficulty, elapsed_days, scheduled_days, learning_steps, reps, lapses, state, last_review`) محفوظة على نموذج `vocabulary` في MongoDB، والمصدر الوحيد للحالة هو قاعدة البيانات (مفيش `localStorage`).
- **الكلمات القديمة** (من قبل الميزة دي) مش محتاجة أي migration: غياب `state` معناه بطاقة جديدة، وبتتحوّل تلقائيًا أول ما تتراجع.
- كل مراجعة بتتسجل في `review_logs` ومبتتمسحش أبدًا (التقييم، الحالة والموعد قبل وبعد، الفترة السابقة والتالية، stability/difficulty قبل وبعد...).
- `week_words` واختبارات المستخدم زي ما هي، ومبتتسجلش كمراجعات FSRS.

### إزاي بتشتغل المراجعة من أولها لآخرها
1. تبويب **المراجعة** بيعرض: المستحق، الكلمات الجديدة المتاحة اليوم، وإنجاز اليوم.
2. «ابدأ المراجعة» بيجيب جلسة: **المستحقة الأول** (`due <= الآن`)، وبعدها كلمات جديدة في حدود الحد اليومي (افتراضي 20، قابل للتغيير من نفس الصفحة).
3. بطاقة واحدة في كل مرة: الكلمة الإنجليزية الأول، وبعد «إظهار الإجابة» بيظهر المعنى والمثال والصور والمرادفات وأزرار **Again / Hard / Good / Easy** وتحت كل زر الفترة الجاية (محسوبة بـ `repeat()`).
4. الضغط على تقييم بيبعت `POST /api/review/:vocabId/rate`؛ السيرفر بيحسب بـ `next()`، بيسجل المراجعة ويحدّث البطاقة، وبعدين بس الواجهة بتروح للي بعدها. لو فشل الطلب بتفضل على نفس البطاقة ومفيش حاجة بتتحفظ.
5. لما الجلسة تخلص بتظهر رسالة بعدد البطاقات ونسبة التذكّر وأقرب مراجعة جاية. اختصارات الكيبورد: `Space` يظهر الإجابة، و`1-4` للتقييم.

### الـ APIs الجديدة (كلها تحتاج تسجيل دخول، والمستخدم بيتحدد من الـ token فقط)

| Method | Path | الوصف |
|---|---|---|
| GET | `/api/review/summary?tz=` | المستحق الآن، الجديد المتاح، إحصائيات اليوم وآخر 7 أيام، أقرب موعد جاي |
| GET | `/api/review/due?limit=&tz=` | بطاقات الجلسة (المستحقة ثم الجديدة) + `preview` لكل زر |
| POST | `/api/review/:vocabId/rate` | `{ "rating": "Again\|Hard\|Good\|Easy", "request_id": "<uuid>" }` ← الموعد التالي |
| GET | `/api/review/history?limit=&skip=` | سجل المراجعات من الأحدث للأقدم |
| GET / PUT | `/api/review/settings` | `{ "daily_new_limit": 0-500 }` |
| GET / PUT | `/api/reminders/settings` | `{ "enabled": true, "time": "20:00", "timezone": "Africa/Cairo" }` |
| POST | `/api/reminders/subscribe` | `{ "subscription": <PushSubscription>, "timezone": "..." }` |
| POST | `/api/reminders/unsubscribe` | `{ "endpoint": "..." }` |

أكواد الأخطاء: `400` مدخلات غلط (`INVALID_RATING`, `INVALID_ID`, `INVALID_REQUEST_ID`...)، `404` الكلمة مش بتاعت المستخدم، `409` (`NOT_DUE` البطاقة مش مستحقة، `CONFLICT` اتغيّرت من طلب تاني، `REQUEST_ID_REUSED`)، `503` الإشعارات مش متظبطة.

**منع التكرار:** كل ضغطة ليها `request_id` (الواجهة بتولّده)، وفيه index فريد على `(user_id, request_id)`؛ نفس الطلب لو اتبعت تاني بيرجّع نفس النتيجة من غير سجل جديد. وكمان البطاقة اللي لسه مش مستحقة بتترفض بـ `409`، وتحديث البطاقة مشروط بإن عدد مراجعاتها (`reps`) ما اتغيّرش.

**الاتساق من غير Transactions:** MongoDB المستقل (standalone) مبيدعمش transactions، فالتنفيذ بالترتيب ده: تسجيل المراجعة ← تحديث البطاقة المشروط ← لو التحديث فشل بيتمسح السجل ويرجع خطأ. ولو السيرفر وقع بين الخطوتين، إعادة إرسال نفس `request_id` بتكمّل التحديث الناقص.

## التذكيرات اليومية (Web Push)

1. ولّد مفاتيح VAPID مرة واحدة: `cd server && npx web-push generate-vapid-keys`
2. حطها في `server/.env` (الشكل في `.env.example`): `VAPID_PUBLIC_KEY` و`VAPID_PRIVATE_KEY` و`VAPID_SUBJECT=mailto:you@example.com`. المفتاح الخاص يفضل على السيرفر بس، ومتغيّرش الزوج بعد ما المستخدمين يشتركوا.
3. من تبويب المراجعة المستخدم يضغط **«شغّل التذكير»** (الإذن بيتطلب وقتها بس، مش عند فتح الصفحة)، ويختار الوقت. المنطقة الزمنية بتتاخد من المتصفح وبتتخزن.

- المؤقّت بيشتغل جوه السيرفر (كل دقيقة)، وبيرسل في وقت المستخدم المحلي، **مرة واحدة في اليوم**: بيتحجز في MongoDB بعملية atomic لكل مستخدم وتاريخ محلي، فمفيش تكرار حتى لو PM2 فيه أكتر من عملية. لو مفيش مراجعات مستحقة ولا كلمات جديدة مش بيتبعت إشعار.
- لو السيرفر كان واقف في وقت التذكير بيتبعت متأخر لحد `REMINDER_CATCHUP_MINUTES` (120 افتراضي)، وبعدها بيتخطّى ليوم تاني.
- الاشتراكات المنتهية (`404/410`) بتتمسح، وكمان اللي بتفشل بشكل متكرر. وإيقاف التذكير أو إلغاء آخر اشتراك بيوقف الإرسال.
- من غير مفاتيح VAPID: التذكيرات متقفلة بس وبتظهر رسالة واضحة، والمراجعة شغالة عادي.
- لو بتشغّل أكتر من نسخة وعايز نسخة معينة متشغّلش المؤقّت: `REMINDER_SCHEDULER=off`.

### قيود مهمة (لازم تتقرأ)
- الإشعار والموقع مقفول محتاج: متصفح بيدعم Web Push، وموافقة المستخدم، و**HTTPS** في النشر (`localhost` مقبول للتجربة).
- المؤقّت جزء من عملية السيرفر. **لو الاستضافة المجانية بتنيّم السيرفر عند عدم الاستخدام (زي خطط Render/Railway المجانية) التذكيرات مش هتوصل في ميعادها** وهتوصل متأخرة أو متتخطّاش لما السيرفر يصحى. للتشغيل الفعلي استخدم استضافة شغّالة دايمًا (VPS/PM2 أو خطة مدفوعة بدون sleep)، أو شغّل نسخة صغيرة دايمة بس لتشغيل المؤقّت.
- آيفون بيدعم Web Push بس لما الموقع يتضاف للشاشة الرئيسية (iOS 16.4+).
